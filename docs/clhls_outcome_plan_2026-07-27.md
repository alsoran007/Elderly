## 0. 一句话摘要

CLHLS **没有死亡日期变量**，只有「区间存活状态」+「各波访问日期」。因此它的 5 年死亡结局在数学性质上不是右删失数据，而是**区间删失（interval-censored）**数据。这与 CHARLS 不同，必须单独处理，且会影响 Aim 1 的统计方法选择。

## 1. 我实测到的 CLHLS 真实结构

### 1.1 文件组织方式和其他队列完全不同

CLHLS 不是「一个主文件 + 各波模块」，而是**每个起始年一个独立的「追踪到 2018」文件**：

| 文件 | 大小 | 含义 |
|---|---|---|
| `clhls_1998_2018_longitudinal_...sav` | 61 MB | 1998 入组者追到 2018 |
| `clhls_2000_2018_...sav` | 71 MB | 2000 入组者追到 2018 |
| `clhls_2002_2018_...sav` | 99 MB | 2002 入组者追到 2018 |
| `clhls_2005_2018_...sav` | 86 MB | 2005 入组者追到 2018 |
| `clhls_2008_2018_...sav` | 80 MB | 2008 入组者追到 2018 |
| **`clhls_2011_2018_...sav`** | **36 MB** | **2011 入组者追到 2018 ← 本项目用这个** |
| `clhls_2014_2018_...sav` | 16 MB | 2014 入组者追到 2018 |
| `clhls_2018_cross_sectional_...sav` | — | 2018 横断面，无随访，不用 |

**选 2011 文件的理由**：与 CHARLS 2011 基线年份对齐，消除时期效应（医疗水平、死亡率长期趋势）这一混杂。这是 Aim 1 能成立的前提——如果 CHARLS 用 2011、CLHLS 用 2008，那性能差异里就混进了时期效应，无法归因于队列差异。

### 1.2 关键实测数字（2011–2018 文件）

```
N = 9,765
变量数 = 3,046
基线访问年：2011 = 7,328 人；2012 = 2,437 人   ← 注意跨两年
```

**基线跨 2011 和 2012 两年**，这一点后面要处理。

### 1.3 死亡信息的真实形态

只有两个状态变量，**没有任何死亡日期变量**（我搜遍了 `dth*`、`yeard*`、`monthd*`、`deathy*` 等所有可能命名）：

**`dth11_14`** — label: *status of survival, death, or lost to follow-up from 2011/2012 to 2014 waves*

| 取值 | 人数 |

| lost to follow-up in the 2014 survey | 820 |
| died or lost to follow-up in previous waves | 0 |
| **合计** | **9,765** ✅ |

**`dth14_18`** — label: *status of survival, death, or lost to follow-up from 2014 to 2018 waves*

| 取值 | 人数 |

## 2. 核心问题：这是区间删失数据

### 2.1 问题的本质

CHARLS 的死亡数据长这样：

```
基线 2011-07 ──────────── 死亡 2013-03-26 ← 有具体日期
                          time_to_event = 604 天
```

CLHLS 的死亡数据长这样：

```
基线 2011-08 ──────?????────── 2014 访问期
                                 只知道「在这之前死了」
              死亡发生在这个区间内的某一点，但不知道是哪一点
```

**已知**：基线访问日期（精确到日）、2014 年访问期。
**未知**：死亡的具体时点。

区间宽度约 **2.5–3 年**，而我们的主结局窗口是 5 年。**这意味着相当一部分死亡无法明确判定是否落在 5 年内。**

### 2.2 这为什么是个真问题

假设某人 2011-08-15 基线，`dth11_14 = died before 2014 survey`。2014 年访问期是 2014 年 4–11 月。那么此人死于 2011-08-15 到约 2014-11 之间，即基线后 0 到约 1,190 天。

**这个区间完全落在 5 年（1,826 天）之内**，所以此人无论死在区间哪一点，`event_5y = 1` 都成立。✅ 这类没问题。

问题出在第二区间。某人 `dth14_18 = died before 2018 survey`，死亡区间是 2014 年访问期到 2018 年访问期，即基线后约 1,000 到约 2,600 天。**这个区间跨越了 1,826 天这条线。** 此人可能死在第 1,200 天（算 5 年内事件），也可能死在第 2,400 天（5 年时仍存活，应删失）。

**用不同假设会得到不同的 5 年死亡数。这个差异不是小数点后的问题，可能有几百人。**

### 2.3 三种处理方案

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 区间中点插补** | 死亡时间 = 区间中点 | 简单，可直接用标准 Cox | 引入系统性偏倚，低估早期死亡 |
| **B. 真区间删失模型** | 用 `icenReg` / `interval` 包做区间删失生存分析 | 统计上正确 | 与 CHARLS 的模型不同，**跨队列可比性受损** |
| **C. 改用区间对齐的结局** | 主结局改为「到 2014 波的死亡」（约 2.5–3 年），而非 5 年 | 完全避开区间跨越问题 | 与 CHARLS 5 年结局不可比，Aim 1 逻辑要重写 |

### 2.4 我的建议：A 为主 + B 为敏感性分析

**主分析用方案 A（区间中点）**，理由：

1. **可比性优先。** Aim 1 的科学问题是「CHARLS 训练的模型在 CLHLS 上还准不准」。要回答这个，两边的结局定义必须一致。如果 CLHLS 用区间删失模型、CHARLS 用标准 Cox，那 C-index 的差异里就混进了「方法差异」，无法归因于「队列差异」——这会毁掉 Aim 1 的论证。
2. **预测模型验证的性质。** 我们不是在估计 FI 的因果效应（那种情况下区间删失的偏倚会直接污染系数），而是在检验一个**已冻结模型**的判别与校准。判别（C-index）依赖的是风险排序，对死亡时点的中等误差相对稳健。
3. **可辩护。** 区间中点插补是队列研究的标准做法，文献中大量使用，写清楚即可。

**同时必须做方案 B 作为预先规定的敏感性分析**，用 `icenReg` 拟合区间删失模型，比较 C-index 与校准。若两者结论一致 → 强稳健性证据；若不一致 → 必须在 Discussion 中如实讨论，这本身也是有价值的方法学观察。

**审稿人一定会问这个问题。** 主动做 B 并报告，比被问到再补做要好得多。

## 3. 技术障碍：Python 读不了 CLHLS

**实测结果**：`pyreadstat` 读 `clhls_2011_2018_...sav` **完全失败**，四种编码（gb18030 / gbk / latin1 / utf-8）全部报同一个错：

```
<method 'get' of 'dict' objects> returned a result with an exception set
```

`metadataonly=True` 和 `row_limit=5` 两种绕法都不行。这是 pyreadstat 在处理该文件的值标签字典时的 bug。

**R 的 `haven::read_sav()` 读取成功**，正常返回 9,765 × 3,046，中文标签也能读出来。

### 因此 CLHLS 的技术路线必须调整

| 步骤 | 工具 |
|---|---|
| 读取 `.sav` + 变量筛选 | **R `haven`**（Python 不可用） |
| 转成中间格式 | R `arrow::write_parquet()` |
| 后续清洗、FI 构建 | Python（读 parquet） |
| 区间删失敏感性分析 | R `icenReg` |

这与 CHARLS（纯 Python）不同。要在代码库里明确记录这个差异，`code/01_extract/` 下 CLHLS 的提取脚本是 `.R` 而不是 `.py`。

**顺带一个提醒**：CLHLS 的 codebook 是 `.docx` 格式（8 个文件，在 `CLHLS_codebook 1998-2018/`），需要 `python-docx` 或转换工具来读。变量映射时必须查 codebook，因为 CLHLS 的变量命名（`a1`、`a2`、`d1`、`e1` 之类）完全无法从名字猜含义。这是三个自建队列里查 codebook 成本最高的。

## 4. 基线定义方案

### 4.1 基线日期

CLHLS 基线跨 2011（7,328 人）和 2012（2,437 人）两年。**不能统一假定一个日期**，必须用个体实际访问日期：

```
baseline_date = make_date(yearin, monthin, dayin)
```

好消息：CLHLS 的访问日期**精确到日**，比 CHARLS 好（CHARLS 2011 连月份都没有，只能假定 2011-07-01）。这一点要在论文里说明，因为它影响两个队列随访时间的测量精度——**CLHLS 的时间轴质量优于 CHARLS**，这是个反直觉但重要的细节。

### 4.2 年龄

用 `trueage`（CLHLS 已核验的年龄）。

**CLHLS 的年龄结构是 Aim 1 的核心看点，必须先量化**：CLHLS 刻意超额抽样 80 岁以上和百岁老人。请在诊断报告中给出基线年龄分布（含 80+、90+、100+ 的比例），并与 CHARLS 60+ 的年龄分布并列对比。

这个差异不是数据缺陷，而是**一次天然的年龄结构压力测试**。计划书 7.3 节规定的「限制到 65–85 岁共同重叠区间」敏感性分析，就是为了把「年龄谱不匹配」从「模型不可迁移」中分离出来。

### 4.3 纳入标准

与 CHARLS 保持一致：
- 基线年龄 ≥ 60（CLHLS 实际下限是 65，所以此条基本不排除人）
- 基线存活且完成访问
- FI 可计算（非缺失项 ≥ 80%）—— 本任务不涉及，留待 FI 构建阶段
- 有可判定的随访状态（`dth11_14` 非缺失）

## 5. 结局构建的具体规则

### 5.1 随访状态三分类

| 状态 | 判定规则 |
|---|---|
| `dead` | `dth11_14 == died before 2014` **或** `dth14_18 == died before 2018` |
| `alive_censored` | `dth14_18 == surviving at 2018`（追到 2018 仍存活） |
| `lost_to_followup` | `dth11_14 == lost` 或 `dth14_18 == lost` |

预期人数（基于实测）：
- 死亡：2,879 + 1,837 = **4,716**
- 存活到 2018：**2,884**
- 失访：820 + 1,345 = **2,165**
- 合计：9,765 ✅

**注意失访率 2,165/9,765 = 22.2%**，高于计划书 6.6 节设的 20% 理想值。这需要在论文中专门讨论，并做一个「失访者按最差情况处理」的敏感性分析（假设全部失访者在失访时点死亡，看结论是否翻转）。高龄队列失访率高是常态，但要诚实报告。

### 5.2 死亡时间的区间界定

对每个死亡者，构造区间 `[L, R]`：

**第一区间死亡**（`dth11_14 == died`）：
- `L` = baseline_date（基线后即可能死亡）
- `R` = 该队列 2014 波访问期的**结束**日期

**第二区间死亡**（`dth14_18 == died`）：
- `L` = 该人 2014 年的访问日期（`yearin_14` 等），若缺失则用 2014 波访问期开始日期
- `R` = 2018 波访问期结束日期

**主分析（方案 A）**：`death_date = L + (R - L) / 2`

**敏感性分析（方案 B）**：直接把 `[L, R]` 传给 `icenReg::ic_par()` 或 `ic_np()`。

### 5.3 需要确定的一个参数：各波访问期的起止

`R` 的取值依赖 2014 和 2018 波的访问期范围。这个要从数据里实测，而不是查文献：

```r
# 从存活者的实际访问日期分布推断访问期
range(make_date(yearin_14, monthin_14, dayin_14), na.rm=TRUE)
range(make_date(yearin_18, monthin_18, dayin_18), na.rm=TRUE)
```

请把这两个范围实测出来，并报告分布（月度直方图），因为如果某波访问期跨度很长（比如 8 个月），区间中点的不确定性会更大。

### 5.4 5 年与 8 年事件

```
time_to_event = death_date（中点） 或 last_known_alive_date − baseline_date
event_5y = 1 if time_to_event <= 1826 else 0
time_5y  = min(time_to_event, 1826)
event_8y = 1 if time_to_event <= 2922 else 0
time_8y  = min(time_to_event, 2922)
```

**8 年结局的特别说明**：CLHLS 2011 基线 + 2018 随访 = 约 7 年，**不足 8 年**。所以 CLHLS 的 8 年敏感性分析**做不了**（或者只能做到 7 年）。这与 CHARLS（2011 + 2020 = 9 年）不同。

**这是一个新发现的设计约束**：计划书里的「8 年全因死亡敏感性分析」在 CLHLS 上不可行。建议把敏感性分析的时间窗改为 **7 年**（两队列都能做），或者明确说明 8 年分析仅在 CHARLS 内进行。请在报告里确认 CLHLS 的最大可用随访时长。

### 5.5 必须报告的关键量

**区间跨越 1,826 天的人数**。这是本方案最重要的诊断数字：

```
在第二区间死亡的人中，有多少人的 [L, R] 区间跨越了 1826 天这条线？
```

这个数字直接反映区间中点插补引入了多少不确定性。若这个数很小（比如 < 200），方案 A 的偏倚可忽略；若很大（比如 > 800），必须以方案 B 为主分析，并重新考虑 Aim 1 的方法一致性问题。

**这个数字算出来之前，不要下结论说方案 A 够用。**

## 8. 与 CHARLS 的关键差异汇总表

| 维度 | CHARLS | CLHLS |
|---|---|---|
