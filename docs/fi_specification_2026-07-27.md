## 1. 为什么以 Gateway 定义为准

我们没有 Stata，无法执行 `bbxleyec.do`。但该文件是 **Gateway 官方的权威变量映射规范**，逐行写明了每个标准变量由哪些原始 CHARLS 题目构造、如何编码、如何处理缺失。

因此本项目的策略是：**解析而非执行**。用 Python/R 复刻 Gateway 的官方定义，而不是自己拍脑袋定义 deficit。

**这样做的三个好处：**

1. **可引用性。** 论文方法部分可写 "Deficits were constructed following the Gateway Harmonized CHARLS Version D.2 algorithm (Chen et al., 2025)"，审稿人不会逐个变量质疑。
2. **跨队列可比性。** HRS / ELSA / SHARE / MHAS 的成品 harmonized 文件出自同一套 Gateway 逻辑。若 CHARLS 自建而其他队列用 Gateway，我们无法排除"性能差异来自编码差异"这一致命混杂。以 Gateway 定义为共同锚点可消除该混杂。
3. **可审计性。** 每个 deficit 都有 `.do` 文件的**行号**可回溯，任何人可核验。

**必须诚实报告的局限：** 我们复刻的是 Gateway 的**变量定义**，不是运行了 Gateway 的**程序**。两者在理论上应等价，但实际可能存在细微差异（如缺失码传播、proxy 处理的边界情况）。因此必须做第 6 节的验证。

## 2. FI 的计算规则（Searle 2008 标准）

```
FI = (已有 deficit 之和) / (非缺失 deficit 项目数)
```

取值范围 0–1。**分母是该个体实际有回答的项目数，不是固定的 43。**

**纳入门槛：** 非缺失项 ≥ 80%（43 项中至少 35 项有效）。缺失 > 20% 者删除，**不对 FI 本身做插补**——插补一个衰弱指数会产生难以辩护的循环推理。

**Searle 五条准则的符合性核查：**

| 准则 | 本清单的符合情况 |
|---|---|
| 1. 与健康状态相关 | ✅ 全部 43 项均为公认健康指标 |
| 2. 患病率随年龄上升 | ✅ 需在 Phase 1 用实际数据验证（见 6.2） |
| 3. 患病率不过低（>1%） | 🟡 **待验证**，低于 1% 的项目将剔除 |
| 4. 项目间不高度重复 | 🟡 **待验证**，见 5.3 的相关性检查 |
| 5. 覆盖多个生理系统 | ✅ 7 个域：共病 13 / ADL 6 / IADL 5 / 活动 9 / 感觉 3 / 一般 6 / 认知 1 |

### 3.2 ADL — 基本日常生活活动（6 项）

**关键决策：使用 `a` 版而非 `b` 版。**

Gateway 对每个 ADL 提供两个版本，我已核对 `.do` 第 6479–6600 行确认差异：

| 版本 | 定义 | 编码 | 含义 |
|---|---|---|---|
| **`a`（本项目采用）** | Some difficulty | `db010 ∈ {2,3,4} → 1` | 有困难 |
| `b`（不采用） | Needs help | `db010 ∈ {3,4} → 1` | 需要帮助 |

**自评健康（`shlt`）映射** —— Gateway 编码 1=excellent … 5=poor（`.do` 6249–6253）：

```
1 → 0.00    2 → 0.25    3 → 0.50    4 → 0.75    5 → 1.00
```

⚠️ **CHARLS 的一个坑：** `shlt` 由**两个题目**合成（`da001` 和 `da080`），因为 CHARLS 在问卷不同位置问了两次自评健康，且**选项顺序相反**。Gateway 已统一方向。复刻时必须同时读这两个变量，只用其一会造成大量缺失。

**记忆自评（`slfmem`）映射：** 同 5 分量表，1=excellent → 0，5=poor → 1。

**BMI 切点：已决策采用 WHO 标准（2026-07-27 确认，冻结）**

```
BMI < 18.5      → deficit = 1   （低体重，老年死亡风险显著升高）
18.5 ≤ BMI < 30 → deficit = 0
BMI ≥ 30        → deficit = 1   （肥胖，WHO 标准）
```

实测阳性率 **11.7%**（低体重 6.9% + 肥胖 4.8%）。

采用 WHO 而非中国标准（<18.5/≥28，阳性率 18.1%）的理由：HRS / ELSA / SHARE / MHAS 的 Gateway harmonized 文件均使用 WHO 切点。统一切点后 BMI 这一项才在 7 个队列间可比。牺牲部分中国人群特异性，换取本项目最核心的跨队列可比性。此权衡需写入 Limitations。

🔴 **BMI 的实测核查结果（2026-07-27 已完成，原风险已解除）：**

我实测了 CHARLS 2011 体检模块，结论如下：

| 指标 | 实测值 |
|---|---|
| 基线 N | 17,705 |
| BMI 可计算 | **13,572（76.7%）** |
| BMI 缺失 | 4,133（23.3%） |
| BMI 中位数 | **23.1**（P25=20.8, P75=25.7） |

BMI 中位数 23.1 与中国中老年人群的已发表值吻合，编码方向正确。**缺失 23.3% 落在"纳入但需敏感性分析"区间（10–30%），因此 BMI 保留在 FI 中。**

**⚠️ 变量名的一个重要陷阱（务必注意）：**

CHARLS 2011 体检模块中有**三个**标签含 "Height" 的变量，但只有一个是站立身高：

| 变量 | 标签 | 中位数 | 实际含义 |
|---|---|---|---|
| `qh006` | Height | **43.0** | ❌ 不是身高（疑为坐高或其他部位测量） |
| `qk002` | Knee Height | — | ❌ 膝高 |
| **`qi002`** | Height | **157.9** | ✅ **站立身高（cm），用这个** |
| **`ql002`** | Weight Measurement | **57.7** | ✅ **体重（kg）** |

若误用 `qh006` 作身高，BMI 可计算率会从 76.7% 崩到 **0.5%**——我第一次就踩了这个坑。构建时必须用 `qi002`。

**合理值过滤规则（本项目定义）：**
```
身高有效范围：130–200 cm   （排除 993/999 等缺失码）
体重有效范围：25–150 kg
BMI 有效范围：12–60        （超出视为测量错误，设为缺失）
```

**两种切点标准的实测阳性率：**

| 标准 | <18.5 | 上界 | deficit=1 合计 |
|---|---|---|---|
| **WHO（<18.5 / ≥30）** | 6.9% | 4.8% | **11.7%** |
| 中国（<18.5 / ≥28） | 6.9% | 11.2% | 18.1% |

**建议采用 WHO 标准**，理由：HRS / ELSA / SHARE / MHAS 的 Gateway 文件均用 WHO 切点，统一后 BMI 这一项才跨队列可比。牺牲一点中国人群特异性，换取本项目最看重的可比性。

## 6. `FI_core`：跨队列共同核心版本

除全项 FI 外，另构建一个**只含所有 6 个队列都可得项目**的 `FI_core`（预计 30–35 项）。

**用途：** 作为主分析的敏感性对照。若 `FI_core` 的迁移性能与 `FI_full` 接近，说明结论对 FI 具体构成不敏感——这是一个强有力的稳健性证据，也是审稿人会问的问题（"不同队列 FI 项数不同，怎么能说是同一个预测因子？"）。

**回应逻辑：** ①FI 用比例计算，与项目总数无关；②`FI_core` 敏感性分析结果一致；③引用 Searle 2008 的方法学依据。

`FI_core` 的具体项目清单待 6 队列可得性盘点后确定。
