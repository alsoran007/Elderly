### A-001 · 新增敏感性分析 SA-3（教育调整）

**修订日期**：2026-07-30
**修订类型**：技术错误纠正 → 新增敏感性分析
**⚠️ 结局盲状态**：**否** —— 本修订发生在结局揭盲之后（主分析自 2026-07-29 起完成，见 D-029 至 D-034）。**SA-3 在论文中必须标注为事后（post hoc）敏感性分析，不得表述为预先注册分析。**

#### 修订内容

新增 **SA-3：教育调整模型**。

| 项目 | 内容 |
|---|---|
| 分析范围 | 仅 Aim 1（CHARLS 开发 → CLHLS 外部验证） |
| 主模型（**不变**） | `event ~ fi_full + age + female + factor(period)` |

| 比较指标 | C-index 及 ΔC、O:E、校准截距、校准斜率、Brier、IPA |

D-029 记录教育变量「无法可靠关联」，主分析据此未作教育调整。2026-07-30 的只读可得性排查（`results/education_availability_audit.md`）证明该结论不成立：六队列教育变量全部可得，与 FI-eligible 60+ 分析样本 ID join 率均为 **100.0%**，缺失率 **0.00%–0.53%**。

D-029 误判的技术原因：HRS 教育变量不在 FI 构建所用的 RAND Fat File（`h12f3a.dta`）中，而在 Gateway harmonized 文件（`H_HRS_d.dta`）；MHAS 的 ID 字段为 `rahhidnp` 而非 `unhhid`。

统一尺度为 **ISCED 三分类**：1 = 低于高中；2 = 高中及职业教育；3 = 高等教育。

### A-002 · 执行 SAP §8.1 预设的 cloglog 连接函数分析

**修订日期**：2026-08-01
**修订类型**：技术错误纠正（预设分析遗漏执行）

#### 背景

SAP §8.1 将 logit 与 complementary log-log 两种连接函数**并列为主分析**（原文：「两种连接函数均作为主分析报告」）。稿件 §2.5 已声明二者均已拟合，但仓库中不存在任何 cloglog 输出，该分析实际从未执行。这构成已声明但未执行的分析，属 TRIPOD+AI 下的严重报告缺陷。

#### 处理

补做执行，而非删除声明。实施脚本 `code/04_model/run_cloglog_sensitivity_2026-08-01.R` 完整复用 Aim 1 管线（同一 person-period 结构、同一完整案例样本、同一 CLHLS 外部验证流程），仅将 `binomial(link = "logit")` 改为 `binomial(link = "cloglog")`。脚本同时重算 logit 分支作为回归测试：内部 C = 0.770525、外部 C = 0.838938、n = 7,546 / 7,095，与既有 Aim 1 输出逐位一致，确认管线等价。

#### 结果与对稿件的影响

| 指标 | logit | cloglog | 绝对差 |
|---|---:|---:|---:|
| 内部 C（Model B） | 0.7705 | 0.7705 | 0.00002 |
| 内部 ΔC（B−A） | 0.0351 | 0.0349 | 0.00013 |
| CLHLS 外部 C | 0.8389 | 0.8389 | 0.00007 |
| O:E | 1.247 | 1.216 | 0.031 |
| 校准斜率 | 0.939 | 0.833 | 0.106 |
| IPA | 0.2957 | 0.2934 | 0.0023 |

**判别对连接函数不敏感（C 最大差 0.0001），但校准敏感（斜率差 0.106）。** 稿件原先声称两种连接函数结果「一致到 0.001 以内」，该表述对判别成立、对校准不成立，已按实测值改写。因本研究 H1–H6 全部判定标准建立在判别与重校准行为之上，而非冻结 logit 模型的绝对校准，故结论不变；保留 logit 为主规格以维持 OR 尺度可解释性。

### A-003 · 指标集与推断方法的执行偏离（回溯记录）

**修订日期**：2026-08-01
**修订类型**：技术错误纠正（预设分析未执行）
**⚠️ 回溯性质**：本条为**回溯记录**，违反本日志「不可回溯补写」规则。偏离发生于 2026-07-29 主分析执行时，直至 2026-08-01 稿件审计才被发现。此处如实记录该时序，不作掩饰；本条不主张这些偏离曾获事前批准。

#### 偏离一：Uno C-index 与 4 年 time-dependent AUC 从未实现

SAP §9 将三项判别指标并列（Harrell C、Uno C、Blanche 4 年 time-dependent AUC），其中 Uno C 明确标注「对删失更稳健，审稿人常要求」。实际仅实现 Harrell C：`code/` 全目录检索 `UnoC`、`uno_c`、`timeROC`、`Score(` 均无命中，`survival`／`riskRegression`／`timeROC` 的相应函数从未被调用。

**影响评估**：本研究结局为固定 4 年窗口的二分类事件，采用 person-period 汇总 logistic 结构而非连续时间生存模型。在该设定下 Harrell C 等同于二分类 AUC，不存在 Uno C 所要纠正的删失导致的偏倚；4 年 time-dependent AUC 亦退化为同一量。因此三者在本设计下数值等价，缺失不改变任何判别结论。SAP §9 的三指标并列反映的是连续时间框架的惯例，与最终采用的离散时间设计不匹配——这是 SAP 撰写时的设计-指标错配，而非分析执行错误。

**处理**：不补做（在本设计下无信息增量）。已在稿件 §2.11 说明为何单一 Harrell C 在离散时间设定下即为充分。

#### 偏离二：bootstrap 迭代次数低于预设

SAP §8.3 规定「置信区间：bootstrap 1000 次迭代」。实际执行值：

| 分析 | 脚本位置 | 实际 B | SAP 规定 |
|---|---|---:|---:|
| Aim 1 外部 C 的 CI | `run_aim1_charls_clhls_2026-07-29.R:216,227` | 500 | 1000 |
| Aim 2／Aim 3 各队列 CI | `run_aim2_loco_2026-07-29.R:61`、`run_aim3_asian_pool_2026-07-29.R:14` | 300 | 1000 |
| 乐观度校正、H3 降采样对照 | `run_aim2_loco_2026-07-29.R:170` | 200 | 1000 |

**影响评估**：bootstrap 迭代数只影响 CI 端点的蒙特卡洛误差，不影响点估计。在 B = 300 时百分位 CI 端点的蒙特卡洛标准误约为 bootstrap 分布标准差的 0.08 倍；本研究报告的 CI 宽度（如 Aim 1 外部 C：0.8301–0.8481，宽 0.018）远大于该量级，故所报区间在已报告的四位小数上稳定。H1–H6 的全部判定阈值（ΔC ≥ 0.02、ρ ≥ 0.70 等）均基于点估计而非 CI 端点，结论不受影响。

**处理**：不重跑。稿件已在各处如实标注实际迭代数（§2.8 的 B = 200、§2.6 的 200 次降采样），未出现「1000 次」表述，故不存在与实际执行不符的声明。此条记录的是 SAP 与执行之间的差异，而非稿件与执行之间的差异。

#### 偏离三：家庭／PSU 聚类标准误未采用

SAP §8.3 规定开发集「标准误按家庭/PSU 聚类校正」，§8.3 并要求 bootstrap「按家庭/PSU 分层聚类重采样」。实际全部采用个体层面的独立性假设：Model A/B 的 SE 为标准 MLE 输出，bootstrap 为 person-level 重采样（稿件 §2.4 已明示 "person-level bootstrap"）。

**影响评估**：这是三项偏离中唯一可能实质影响推断的一项。CHARLS 按家庭户抽样，同户成员的死亡风险存在正相关（共享环境、社会经济地位、照护资源），忽略聚类会**低估**标准误、使 p 值偏小、CI 偏窄。方向明确：现报告的 Model B 系数 CI 偏于乐观。

但对本研究主要结论的影响有限，原因有三：(1) 本文核心主张是判别与校准的**跨队列可迁移性**，其判定基于 C-index、O:E、校准斜率等预测性能指标，这些指标的点估计不受聚类结构影响；(2) FI 系数的统计显著性极强（β = 2.4839，p < 2×10⁻¹⁶），即使 SE 按典型家庭内相关（设计效应约 1.2–1.5）放大，仍远离任何常规显著性边界；(3) 外部验证队列的性能评估不依赖开发集 SE。

**处理**：不重跑（CHARLS FI 分析文件未保留家庭标识符，补做需回溯至原始 `demographic_background.dta` 重建 household ID 并重跑全部 Aim 1 管线）。已在稿件 Limitations 新增一条如实披露该偏离及其方向性影响，供审稿人判断。

#### 本修订不变更的内容

主模型规格、H1–H6 假设及方向、已报告的主分析点估计、FI 构建规范、结局定义。

#### 关联文档

- 稿件位置：§2.11（判别指标说明）、Limitations 第 11 条（聚类标准误披露）

### A-004 · Model C（H5 内在能力分析）规格补记

**修订日期**：2026-08-01
**修订类型**：SAP 要求的独立修订（补记）

#### 背景

SAP §8.2 将 Model C 定义为 `logit(P_t) = Model B + IC_score`（增量模型），并明确声明：「由于 IC 构建规格尚待确定，Model C 不在本 SAP 主分析中冻结，**须在独立 SAP 修订中规定**」。该独立修订此前未撰写——H5 分析已于 2026-07-30 执行完成（`results/h5_ic/`），但其规格从未按 SAP 要求正式记录。本条补足该缺口。

#### 实际执行规格

H5 分析实际采用**替代**而非增量结构：

| 模型 | 规格 |
|---|---|
| SAP §8.2 设想（增量） | `event ~ fi_full + age + female + period + IC_score` |
| 实际执行（替代） | Model C：`event ~ IC 五域 + age` |

改为替代结构的理由：IC 五域（认知、心理、活力、感觉、运动能力）与 FI 的 41 个 deficit 在条目层面高度重叠——IC 的运动能力域直接取自 FI 的 Mobility 条目，活力域取自 FI 的体重／疲乏条目。在同一模型中同时纳入 FI 与 IC_score 会产生结构性共线，其系数无法解释为「IC 的增量贡献」。替代结构改问一个可回答的问题：**以 IC 框架重新组织同一批底层条目，能否达到 FI 的判别水平**。

#### 对 H5 判定的影响

H5 因此被判定为「**初步成立**」而非「成立」，并全程标注为补充分析。稿件 §3.9 与判定表均采用该措辞（CN 版此前存在「H5 成立」的不一致表述，已于 2026-08-01 修正为「初步成立」）。ΔC 的解释亦相应受限：其量度为两种条目组织框架的判别差异，而非 IC 相对 FI 的增量价值。

### A-006 · H6 特征粒度由聚合 FI 变更为 FI_core 19 分项

**日期**：2026-08-02
**类型**：检验实现规格补记（回溯）
**触发**：H6 判据「年龄和 FI 始终位居前三」在实际执行中无法按字面套用

#### SAP 原文

SAP §14 H6：「SHAP 特征重要性排序跨队列 Spearman 相关 ≥ 0.7，**年龄和 FI 始终位居前三**」
检验方式：「逐队列 SHAP + 跨队列排序矩阵」

#### 实际执行（2026-07-29，D-033）

特征集为 **FI_core 19 个分项 + 年龄**（共 20 个特征），而非「聚合 FI + 年龄 + 性别」。重要性度量为 `|β_standardised|`（主效应 GLM 的线性 SHAP，对该模型类精确成立）。

#### 变更理由

若按 SAP 字面使用聚合 `fi_full` 作单一特征，模型仅含 2 个特征（fi_full + age），则：
1. 「位居前三」在 2 特征模型中恒真，判据无信息量
2. 跨队列 Spearman 在 2 个特征上恒为 ±1，无法反映真实一致性
3. H6 的科学意图（哪些具体健康缺陷跨队列稳健预测死亡）无法回答

改用 FI_core 19 分项使跨队列排序矩阵具备 20 个特征的可比维度，符合 H6 的原始科学目的。

#### 对 H6 判定的影响

| SAP 判据 | 实际可检验形式 | 结果 |
|---|---|---|
| Spearman ≥ 0.70 | 20 特征跨 6 队列成对 Spearman 中位数 | **0.41**（未达阈值）❌ |
